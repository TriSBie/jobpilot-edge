Không migration nào sau 0001 thêm index. `ALTER TABLE ADD COLUMN` (0002, 0006, 0007, 0008) **không idempotent** — chạy lại sẽ lỗi "duplicate column".

⚠️ **Rủi ro chính:** README (dòng 162–164) hướng dẫn chạy migration bằng `d1 execute --file`, **không** phải `d1 migrations apply`. Vì vậy bảng nhật ký `d1_migrations` trên prod rất có thể trống hoặc không tồn tại, và `wrangler d1 migrations list` (thư mục mặc định `migrations/` cạnh wrangler.toml, repo dùng `db/migrations/`) sẽ không phản ánh đúng. **Không chạy `d1 migrations apply` lên prod** trước khi đối chiếu xong — nó có thể chạy lại 0004 (DELETE) và 0007 (UPDATE). Bằng chứng thật về migration đã áp là **schema** (mục 3b), không phải nhật ký.

## 3. Lệnh CHỈ ĐỌC để anh chạy trên prod

Chạy trong `apps/api/` (nơi có wrangler.toml thật). Thay `jobpilot` nếu tên DB khác. Tất cả đều là SELECT/PRAGMA/list — không ghi.

### 3a. Nhật ký migration

```bash
npx wrangler@4 d1 migrations list jobpilot --remote
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT name FROM sqlite_master WHERE type='table' AND name='d1_migrations'"
# nếu bảng trên tồn tại:
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT id, name, applied_at FROM d1_migrations ORDER BY id"
```

### 3b. Schema — bằng chứng từng migration

```bash
# 0002/0006/0008: cột trên users (mong đợi có password_hash, consent_cv_at, deleted_at, telegram_chat_id, digest_hour)
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT name, type, dflt_value FROM pragma_table_info('users')"
# 0007: cột trên jobs (mong đợi last_seen_at, seen_count, repost_count)
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT name, type, dflt_value FROM pragma_table_info('jobs')"
# 0003/0005: bảng mới
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"
# Index (so với 0001; 0007/0008 không thêm index — kiểm xem prod có index lạ/thiếu)
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT tbl_name, name, sql FROM sqlite_master WHERE type='index' AND sql IS NOT NULL ORDER BY tbl_name, name"
```

### 3c. Dữ liệu 0007 / 0008 (đếm, không ghi)

```bash
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT COUNT(*) AS total, SUM(last_seen_at IS NULL) AS null_last_seen, MIN(last_seen_at), MAX(last_seen_at) FROM jobs"
npx wrangler@4 d1 execute jobpilot --remote --command "SELECT COUNT(*) AS users, SUM(telegram_chat_id IS NOT NULL) AS tg_linked, SUM(digest_hour IS NULL) AS null_digest_hour FROM users"
```

Câu 3c lỗi "no such column" = migration tương ứng **chưa áp** trên prod.

### 3d. Queue hiện có (chỉ liệt kê)

```bash
npx wrangler@4 queues list
npx wrangler@4 queues info jobpilot-ingest   # xem consumer + DLQ đang cấu hình (lặp cho score, notify)
```

## 4. Lệnh tạo 3 DLQ (GHI lên prod — cấu hình đã chốt 06/11; chỉ chạy lúc release)

```bash
npx wrangler@4 queues create jobpilot-ingest-dlq
npx wrangler@4 queues create jobpilot-score-dlq
npx wrangler@4 queues create jobpilot-notify-dlq
```

Theo docs Cloudflare Queues (kiểm 06/11/2026): nếu DLQ tên trong `dead_letter_queue` chưa tồn tại thì deploy sẽ tự tạo; tạo trước vẫn nên làm để kiểm soát tên/retention. DLQ không có consumer → message nằm đó tới hết thời hạn lưu (retention) của queue, không tự replay. Chưa có consumer/alert cho DLQ — việc tiếp theo nếu cần.

Thứ tự release (ROADMAP Bước 3 A1): đối chiếu mục 3 → tạo DLQ → migration còn thiếu (chạy **từng file** `d1 execute --file`, không `migrations apply`) → Worker → Pages.
